# 관계 추론과 조건 규칙 점검 (2026-11-10)

## 이전 받친글자 경로 (아래 구현 업데이트 이전)

작업 화면의 받친글자 목표 공간, 코너 안내, SVC location 목표는
`mieum_relations.estimate()`를 사용한다. `RelationModel.calibrated()`에는 공통 표본
3개 이상에서 회귀/가림 검증을 하는 별도 로직이 있지만, 그것이 받친글자 SVC의
직접적인 후보 선택기로 사용되는 것은 아니다.

1. 대상 글자가 실측 표본이면 그 값을 사용한다.
2. 초성은 같은 중성의 대상 초성+ㅁ받침을 기준으로 삼는다.
   예: 볾 초성 크기 = 봄 초성 크기 × 옮 초성 크기 / 옴 초성 크기.
   전이 기준이 ㅇ이라는 전제다. 자동 기준은 같은 모임꼴·받침 유무에서 표본 수로 정한다.
3. 종성은 같은 중성의 초성ㅁ+대상 종성을 기준으로 초성 교체 효과를 반영한다.
   예: 볾 종성 크기 = 몲 종성 크기 × 봄 종성 크기 / 몸 종성 크기.
4. 중성은 초종성ㅁ 기준에 초성 및 종성 교체 효과를 적용한다.
5. 필요한 표본이 없으면 실제 기준 초성의 같은 중성·종성 글자를 찾는다.
   대상 초성의 ㅁ받침 보정쌍은 같은 중성을 우선하고, 없으면 같은 모임꼴의
   다른 중성(현재 Unicode 순서)을 사용한다. 종성·중성에는 초종성ㅁ 프레임도 요구한다.
6. 크기는 비율, 위치는 차이를 전이하고 수동 보정량을 별도로 더한다.

볼·볽이 있어도 가까운 받침이라서 우선하는 단계는 없다. ㄹ/ㄺ/ㄻ/ㄼ의
측정 유사성을 역할·문맥별로 승인하여 공유하는 규칙도 현재 없다.
H/V/M 및 민글자/받친글자는 분리한다.

## 가까운 근거 사용 설계

- 단순히 받침 이름이 비슷하다고 동일 그룹으로 묶지 않는다.
- 같은 초성·중성의 직접 표본을 배치 기준 후보로 삼고, 다른 표본 계열에서
  확인한 받침 간 대비를 적용한다. 예: 볾 초성 = 볽 초성 × 옮 초성 / 옭 초성.
- 볼·볽 사이의 관측 변화가 기준 계열의 올·옭 대비와 부합하는지 비교한다.
  후보가 여러 개면 관측 대비의 재현 오차와 지원 문맥 수를 사용한다.
- 볼·볽 두 글자만으로 볾·볿도 동일하다고 확정하지 않는다. 해당 받침으로 가는
  측정 대비나 사용자가 승인한 공유 규칙이 필요하다.
- 초성/중성의 공간 공유와 종성 윤곽 공유는 다르다. ㄺ 윤곽을 ㄻ 대신 쓰지 않는다.
- 선택한 기준 글자, 대비 표본, 근거 부족/충돌 상태를 기록한다.

## 조건별 별도 SVC 소스 (설계 확인 대기)

현재 소스 연결 키는 역할 + 자소 + H/V/M + 받침 유무다.
예: ㄷ 초성의 다+받침과 더+받침은 같은 H/closed 키라 서로 다른 소스를
지속적으로 배정할 수 없다. UI에 숨겨진 완성 기능이 있는 상태가 아니다.

필요한 최소 규칙은 대상 역할, 초중종 조건 집합, 연결 소스 이름이다.
예: 역할=초성, 초성={ㄷ}, 중성={ㅓ,ㅕ}, 종성={받침 있음}, 소스=별도 ㄷ.
조건 규칙이 없으면 기존 연결을 사용하고, 중복 매칭으로 소스가 다르면 충돌을 표시한다.
윤곽 분기와 수치 보정 규칙은 구분한다. 사용자의 범위 확인 후 구현한다.

## 이번에 구현한 작업 흐름

- 새 소스 note: 역할/모임꼴/원점 한 줄 + 코너당 location, 예상 W/H, 조건 글자 하나.
  공통 극값 글자가 없으면 `참고`, 추정 치수가 없으면 `W/H 미정`으로 표시한다.
- `필요한 디자인 확인 → 표본 재측정·안내 갱신`: 표본 탭 문자열을 현재 마스터에서
  다시 측정하고 추론한다. 기존 목표 보정이 있으면 삭제 확인을 거친다.
  연결/기존 소스의 안내와 note만 갱신하며 윤곽·레이어·적용 SVC는 바꾸지 않는다.
  필요시 사용자가 코너 디자인을 조정하고 선택 자소에 다시 적용한다.
- note의 관리 블록 밖 사용자 메모는 보존한다. 과거 안내 전체와 정확히 일치하는
  기존 생성 note는 짧은 형식으로 교체한다.
- `문자 범위 → 2,350/2,780 → 범위만 보기`: 범위 밖 글자를 보기와 선택에서 제외한다.
  표본 자체를 삭제하거나 추론 근거에서 제외하지 않는다.

## 구현 업데이트: 실측 대비 전이 및 기존 SVC 재계산

- 실측 우선. 그 다음 `local_relations.local_transfer()`를 거치고, 유효 후보가 없을 때
  이전 ㅁ 기준 경로를 사용한다. 충돌은 이전 경로로 숨기지 않고 오류로 남긴다.
- 대상 역할의 자소는 유지하고 다른 조건 한 개만 교체한다. 비교 계열도 다른 조건
  한 개만 차이나야 한다. 같은 H/V/M·받침 유무 안의 실제 표본만 사용한다.
- 대응 기준 계열에서 목표 자소 bbox와 가까운 공통 실측 조건 두 개를 먼저 고른다.
  크기 차이와 위치 차이를 각각 bbox W/H로 정규화하여 거리를 계산한다.
  두 조건을 번갈아 가려 크기 비율·위치 차이 전이가 재현되는지 검사한다.
- 현재 허용 오차는 W/H 각각 max(1 unit, 2%), X/Y 각각 2 unit이다.
  이는 초기 공학적 기준이지 통계적 신뢰도나 미적 타당성 보장이 아니다.
- 검증을 통과한 후보는 가까운 실제 글자에서 한 단계로 전이한다.
  다른 유효 후보와 허용 오차 이상 불일치하면 `관계 충돌`로 표시한다.
  재귀 전이, 추정 결과 재학습, 자소 이름에 따른 강제 그룹화는 하지 않는다.
- 기준 초성 선택은 기존 ㅁ 기준 fallback에 적용된다. 실측 대비 경로는 같은 모임꼴의
  다른 초성도 비교하므로 사용자 지정 기준 초성 하나로 제한하지 않는다.
- 표본 재측정 후 기존 SVC 전체 재계산을 확인창으로 제안한다. 소스 디자인을
  직접 바꾼 경우 별도 `기존 SVC 재계산` 버튼으로 같은 작업을 실행한다.
  실제 소스 응답을 역산하므로 W 극값이 100~200에서 100~300으로 바뀌면
  목표 W150의 width location은 500에서 250으로 바뀐다.
- 코너 안내의 극값 변경과 실제 코너 윤곽 변경은 별개다. 안내 갱신은 윤곽을
  변형하지 않는다. 목표가 실제 소스로 재현 불가하면 기존 SVC를 보존하고 보고한다.
- 조건별 소스/수치 규칙 UI는 여전히 후속 구현 대상이다. 이번 변경이 그 기능까지
  구현했다는 뜻은 아니다.
