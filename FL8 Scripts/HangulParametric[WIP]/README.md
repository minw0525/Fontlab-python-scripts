# Hangul Parametric

FontLab 8용 한글 관계 편집 플러그인. 기존 Composer와 별도 디렉토리에서 개발한다.
Composer는 그룹 기반 컴포넌트 재사용, SmartComponentHangulLab은 연구와 검증,
이 디렉토리는 사용자용 GUI와 FontLab 연결을 담당한다.

## 현재 상태

받친글자 추론에서 초성·종성은 같은 초성·종성의 실측에서 중성만 교체하는 경로를 우선한다.
예: 뱐의 초성/종성은 반 × (얀/안). 중성은 같은 중성을 유지하는 경로를 사용한다.
우선 경로는 공통 실측 한 조건으로도 허용하되 `검증 제한`으로 표시한다.
둘 이상의 조건이 있으면 대비 검증을 수행하며, 유효 후보끼리 충돌하면 우선순위로 숨기지 않는다.
변화율 자체를 증폭하는 가중치는 적용하지 않는다.

관계 충돌 시에도 우선순위 1위의 목표 박스·수치와 SVC 미리보기를 표시한다.
상태는 `우선 추론·충돌`, 상세 패널에는 충돌 기준을 표시한다. 실제 폰트 적용과
자동 재계산도 우선순위 1위 결과를 사용한다. 표본/직접 윤곽 보호와 실제 소스 재현 검사는 유지한다.
충돌 조건은 코너 극값 안내 산정에서는 제외한다.

현재 범위는 **표본 실측 -> 관계 추론 -> 목표 공간 보정 -> SVC 소스 초안/연결 -> 빈 글립 적용**이다.
실측 / 추론 / 근거 부족 / 관계 충돌을 구분한다. 받친글자는 가까운 공통 실측 두 조건에서 검증된 한 조건 교체 관계를 우선한다. 없으면 `mieum_relations.py`의 ㅁ 기준 경로를 사용한다. 예: 막 초성은 맘 × (악/암), 각 종성은 막 × (감/맘). 필요한 실측 조건이 없으면 글자 이름을 명시하고 적용을 보류한다. H/V/M 및 민글자/받친글자는 서로 대체하지 않는다.
SVC 초안은 코너별 가까운 실측 자소를 정규화한 출발점이며 완성 디자인이 아니다.
제작 기준과 남은 정렬 작업은 [RELATION_WORKFLOW.md](RELATION_WORKFLOW.md)를 따른다. 관계 표본의 극값 조건과 대상 자소의 실제 디자인을 구분한다.
신규 소스 note는 코너별 예상 W/H와 조건 글자 하나를 기록한다. 상세 근거는 `필요한 디자인 확인`에서 본다. `표본 재측정·안내 갱신`은 관리 note를 갱신하고 기존 SVC 재계산 여부를 묻는다. 사용자 메모와 소스 윤곽은 보존한다. note 편집 자체는 파라미터에 역반영되지 않는다. sticker 자동 생성은 사용하지 않는다.

소스 코너 윤곽을 직접 수정한 뒤에는 `소스 준비·진단 → 기존 SVC 재계산`을 실행한다.
현재 마스터의 연결된 소스별로 화면 밖을 포함한 기존 컴포넌트의 location과 위치를 갱신한다.
새 삽입이나 마스크 추가는 하지 않는다. 실패 항목은 기존 값을 유지하고 건너뜀 사유를 표시한다.
추정 극값 안내만 바뀌었다고 소스 윤곽을 자동 확대/축소하지 않는다.

실측 표본은 측정과 추론에만 사용하며 모든 SVC 적용 경로에서 항상 제외한다.
표본에 없는 글자라도 직접 윤곽은 교체하지 않는다. 잠금/해제 UI는 없다.
기존 파생 SVC는 현재 역할의 관리 기록 또는 현재 연결 소스와 컴포넌트 참조가
일치할 때 갱신한다. 이전 버전에서 삽입해 관리 기록이 없어도 연결 소스가
일치하면 재계산하고 관리 기록을 저장한다. 불일치하는 수동 컴포넌트는 보존한다.
빈 글자에는 생성할 수 있으며 새로 삽입한 SVC의 역할/소스를 Font lib에 기록한다.
이미 SVC인 글자를 실측 표본으로 등록한 경우도 직접 적용은 하지 않지만,
공유 소스 윤곽 수정 자체의 전파를 차단하는 것은 아니다.
width/height만 매핑하며 중성 부가획 semantic axes와 조건별 형태 분기 편집은 아직 연결하지 않았다.

**2026-10-13 검증 중 FontLab 충돌이 발생했다.** 소규모 실측/숫자 편집/드래그는
라이브 검증했지만, 대량 선택을 포함한 후속 테스트에서 Qt backing-store flush가 SIGSEGV로 종료됐다.
정확한 단일 원인은 확정하지 않았다. 큰 QWidget을 스크롤하는 구조를 제거하고 고정 크기 뷰포트와
논리 스크롤바로 변경했다. 2026-10-14 재검증에서는 588자/11,172자 선택,
중간/끝 스크롤, 확대, 미리보기 전환, 숫자/드래그 편집을 충돌 없이 통과했다.
강제 processEvents 호출 없이 단계를 나누어 검사했으므로 이전 충돌의 단일 원인이
확정됐다는 뜻은 아니다. Font lib 메모리 저장/복원은 검증했고 디스크 재열기 검증은 남아 있다.
초기 버전이므로 저장된 테스트용 폰트 사본에서 사용한다.

## 실행

FontLab Scripts에서 `HangulParametric/Run_HangulParametric.vfpy`를 실행한다.
FontLab에 포함된 PythonQt, TypeRig, fontlab을 사용하며 별도 설치나 웹 서버가 필요 없다.

1. 열린 폰트와 마스터를 확인한다. 창은 실행 당시 폰트에 연결된다.
2. 표본 탭에 디자인된 음절 문자열을 입력하고 `표본 측정·관계 추론`을 누른다.
3. 초중종 선택, 글줄 정렬, 중성 배열로 표시 범위를 정한다.
4. 실측/추론 박스를 이동/크기 조절하거나 오른쪽 Δunit 값을 편집한다.
5. 필요한 경우 현재 조건 안의 같은 자소에 변경량을 반영한다.
6. 변경 후 0.8초 동안 입력이 없으면 Font lib에 자동 저장한다. 별도 저장 버튼은 없다.
   창 닫기/마스터 전환 시에도 남은 변경을 저장한다. 디스크 파일 저장은 FontLab에서 수행한다.
7. 자소를 선택하고 `4코너 소스 초안 만들기`로 새 소스를 만들거나 기존 소스 이름을 연결한다.
8. 관계 설정에서 글자를 선택하고 `소스 연결·선택 자소에 적용`으로 SVC를 넣는다. 대상은 선택 글자 중 같은 소스를 쓰는 글자뿐이다. 현재 보기 전체에 적용하려면 먼저 `표시 글자 전체 선택`을 누른다.
9. 연결 후 숫자 조정은 350ms 입력 정지 뒤, 박스 드래그는 마우스를 놓은 뒤 처리한다. 같은 소스의 SVC가 이미 들어 있으면 기존 컴포넌트의 location·transform을 자동 갱신한다. 새 요소나 마스크 백업은 만들지 않는다. 미삽입 글자는 미리보기만 하며 최초 삽입·다른 소스로 교체는 적용 버튼을 누른다. 일괄 입력은 `일괄 목표 반영`으로 확정하면 이미 삽입된 같은 소스 SVC들을 자동 갱신한다. 실패하면 기존 location·transform을 복원한다.
10. 별도 미리보기 탭은 없다. 관계 설정 하단의 `빈 글자 일괄 생성`을 펼치면 제작 문자열과 `FontLab 빈 글립에 SVC 적용`이 나온다. 이 빈 글자 전용 동작은 기존 디자인 및 소스가 모두 연결되지 않은 음절을 건너뛴다.

## 추론과 SVC의 범위

- 표시용 윤곽 읽기와 표본 분석을 분리한다. 분석 표본의 확인된 윤곽은 진하게, 폰트에 존재하지만 분석 표본으로 확인되지 않은 디자인은 고정 회색으로 표시한다. 실제 윤곽이 없을 때만 연한 대체 문자를 표시한다. SVC 평가 색상은 그 위에 유지한다.
- 표시용 윤곽은 현재 마스터의 전경 요소와 컴포넌트를 읽으며 역할 분리가 필요하지 않다. 보이는 글자부터 캐시하고 보기 새로 계산·표본 분석·마스터 전환·빈 글자 적용 시 캐시를 갱신한다. 이 동작은 표본, 추론 결과, Font lib를 변경하지 않는다.

- Lab `select_relation`을 재사용하여 identity/translation/affine 관계를 교차검증한다.
- 같은 초성의 모음 간 공통 종성, 또는 초성 간 공통 (중성, 종성) 표본이 최소 3개일 때만 전이한다.
  H/V/M 및 받침 유무는 서로 섞지 않는다. 학습 입력은 실측뿐이고 추론값을 재학습하지 않는다.
- 초중종의 전체 공간 프로필을 함께 추정하지만 인과적 제약 최적화 모델은 아니다.
  박스를 직접 바꿨다고 다른 자소의 공간을 자동 재계산하지 않는다.
- 근거 음절, 관계별 교차검증 MAE, 여러 추정 사이 최대 차이를 표시한다. MAE는 해당 관계의
  표본 검증값이지 새 글자 디자인의 정확도 보증이나 신뢰구간이 아니다.
- 소스 연결 단위는 자소 역할/자소/H·V·M/받침 유무다. 다른 조건별 형태 분기는 후속 작업이다.
- 네 코너 초안은 대상 실측 자소를 원래 크기로 복사하고 원점만 정규화한다. 자동 확대/축소하지 않는다. 관계에서 추정한 극값 조건에 맞춰 직접 디자인해야 하며, 서로 다른 표본의 컨투어 수/노드 수/순서/시작점 호환성도 확인해야 한다.
  원본을 수정하지 않고 새 `_hp.*` 글립에 넣는다. 참고 음절과 극값은 표본 탭 상세에 표시한다.
  획 두께, 곁줄기 위치 등은 반드시 디자인 검토가 필요하다.
- location은 실제 FontLab SVC의 w/h 응답을 수치적으로 역산한다. 두 축이 서로 크기에 영향을
  주는 경우와 상수 축을 처리한다. 0..1000을 벗어나 보외하지 않으며 정수 location에서 크기
  오차가 1 unit을 넘으면 적용하지 않는다. 실제 평가된 원점과 목표 원점의 차이로 이동한다.
- FontLab의 정수 bbox 반환 때문에 location 1 차이가 치수 변화 0으로 보일 수 있다. 변화율 측정 간격을 단계적으로 넓혀 이 경우에도 해를 찾는다. 2026-10-18 실제 소스에서 막 (1000,425), 많·맏 (1000,575), 만 (1000,1000)을 오차 0으로 확인했다. 이전의 오차 10 unit 판정은 이 표본들에서는 소스 문제가 아닌 계산 오류였다.
- 임시 평가용 `_hpProbe.*`는 평가 후 제거한다. 관계 설정의 `소스 연결·선택 자소에 적용`은 최초 삽입·다른 소스로 교체할 때만 자소를 마스크에 추가 백업한다. 같은 소스의 재적용은 기존 컴포넌트를 유지하고 location·transform만 갱신한다. 나머지 자소, 요소 순서, advanceWidth, 기존 마스크와 note는 유지한다.
- 분리 중성 여러 요소는 모두 백업한 뒤 첫 요소 위치의 SVC 하나로 합친다. 이후에는 현재 요소 수에서 역할 인덱스를 다시 계산하여 초성→중성→종성 순서를 유지한다. 자동 recipe 레이어와 역할 구분이 불가능한 글립은 건너뛴다.
- 빈 글자는 해당 유니코드 글립에 적용하며 나머지 역할은 대응 실측 표본에서 복사한다. 별도 `_hpResult.*`는 더 만들지 않고 과거 결과도 삭제하지 않는다. 하단의 빈 글립 전용 적용은 기존 디자인을 계속 건너뛴다.
- 적용 결과에 글자별 location, 이번 마스크 추가 개수, 총 개수를 표시한다. 계산 단계에서 실패했다면 전경을 바꾸거나 백업을 추가하지 않는다. 기존 마스크는 덮어쓰지 않으므로 여러 차례 적용하면 백업이 겹칠 수 있다. 컴포넌트 백업은 참조를 유지하므로 소스 자체를 수정할 때까지 불변인 윤곽 스냅샷은 아니다.
- 삽입 후 위치/크기 오차가 1 unit을 넘거나 윤곽 검증에 실패하면 해당 글자의 전경을 복원하고 이번에 추가한 마스크 백업만 제거한다. 분석 표본 데이터는 자동 재측정하지 않는다.
- 2026-10-14 검증: 당시 저장된 실측 358자에서 904자 추론(ㅁ 110자), 약 1.4초.
  이 표본으로 막·만 등 ㅁ H.closed 조건은 공통 근거가 부족했다. 추론 전체의 디자인 품질을
  검증했다는 뜻은 아니다. 별도 임시 '악' 글립에서 초중종 생성/매핑/삽입과 재적용 보호를 검증했다.

### 표본의 요소 구분

- 기본: 요소 목록 인덱스 0=초성, 1=중성, 2=종성. 민글자는 0, 1만 사용.
- 별도 중성 컴포넌트가 있으면 `분리된 중성 요소 함께 측정` 선택 가능.
  받친글자는 첫 요소=초성, 마지막=종성, 사이의 모든 요소=중성으로 묶는다.
  민글자는 첫 요소=초성, 나머지=중성이다.
- 이 규약은 **사용자가 확인하는 역할 지정**이다. 형태를 보고 자동 판별했다는 의미가 아니다.
  초성/종성 자체가 여러 요소이거나 순서가 다르면 이 버전의 측정 규약에 맞지 않는다.
- 컴포넌트를 분해하거나 재배치하지 않는다. 각 요소의 transform을 반영한 bbox를 합친다.
- 요소 수 오류, 빈 글립, 없는 글립은 사유를 표시하고 분석에서 제외한다.
- 재분석은 기존 보정값을 지우므로 보정이 있으면 확인한다. 유효 표본이 0이면 기존 측정을 유지한다.

### 보기와 편집

- 모든 초성 19 / 중성 21 / 종성 28(없음 포함)을 복수 선택한다. 빈 선택은 0자다.
- `글줄 정렬`은 생성 문자열의 정렬 키, `중성 배열`은 해당 키의 내부 순서다.
- 창은 macOS Qt.Tool 패널이다. FontLab 내부에서 위에 유지되고 앱 비활성 시 숨겨지도록 설정한다. 전역 WindowStaysOnTopHint는 사용하지 않는다.
- 줄바꿈은 `초성·중성별`, `초성별`, `줄바꿈 없음`이다. 창 폭 자동 줄바꿈은 하지 않는다.
  긴 줄은 가로 스크롤하며, 스페이스+왼쪽 드래그 또는 가운데 버튼 드래그로 패닝한다.
  트랙패드 가로/세로 스크롤과 Shift+휠 가로 이동도 지원한다.
- 모임꼴순: `ㅏㅑㅓㅕㅣㅐㅒㅔㅖㅗㅛㅡㅜㅠㅘㅚㅝㅟㅢㅙㅞ`.
- 셀의 가로 간격은 현재 마스터의 advanceWidth를 따른다. 글립/마스터가 없으면 UPM을 사용한다.
- 관계 설정에서도 KS X 1001 2,350자 또는 ADOBE-KR-9 2,780자에 속한 글자의 배경을 표시한다.
  이는 보기 강조일 뿐 제작 타겟이나 추론 범위를 제한하지 않는다.
- 목표 bbox의 X/Y는 왼쪽 아래, Y는 위쪽 양수다. 편집값은 정수로 확정한다.
- 오른쪽 입력은 실측 또는 해당 추론 결과의 보정 전 bbox를 0으로 둔 ΔX/ΔY/Δ너비/Δ높이다.
  기준/목표 절대값은 `계산 근거`를 펼쳐 확인한다. 글자 선택을 바꿔도 기준은 변하지 않는다.
  숫자칸의 휠 증감은 막는다. 키보드 입력과 위아래 버튼으로 수정한다.
- 박스 내부가 겹치면 면적이 작은 박스를 우선 선택한다. 같은 면적은 현재 역할 우선이다.
  선택된 박스의 조절점은 크기 조절을 위해 우선 처리한다. 큰 박스는 바깥쪽 또는 역할 선택기로 선택한다.
- **박스 편집은 원본 윤곽을 변형하지 않는다.** 진한 윤곽은 분석 당시 원본이고,
  색상 박스는 앞으로 SVC를 배치할 목표 공간이다.
- 여러 글자를 선택하면 `선택 글자 함께 조정`으로 전환한다. 같은 역할의 같은 자소에 동일 변경량을 더하며 다른 역할을 임의 재계산하지 않는다.
- 폰트 lib를 다시 읽으면 저장된 측정 스냅샷을 표시한다. 현재 측정과 박스가 일치하는 표본의
  윤곽은 다시 읽어 표시한다. 달라진 표본은 재측정해야 한다.
- 빈 글자 제작 타겟은 관계 설정 하단의 접힌 영역에 있다. 타겟을 바꿔도 표본과 관계 보기 범위는 바뀌지 않는다.
  `현재 보기`는 선택 시점의 문자열을 복사한다. 보기 변경과 영구 연동하지 않는다.
- ADOBE-KR-9 목록은 상위 디렉토리의 `ADOBE-KR-9*2780*.txt`를 읽어 2,780자 여부를 검증한다.

  일치하지 않으면 중단하며, 분석 전이면 빈 세션으로 시작한다. 이미 사라진 분석을 복원하는 기능은 아니다.

## 표본 기준 전이와 배치 보정

- 표본 분석 또는 `저장된 표본으로 관계 재추론`으로 다시 계산한다. 대상 자소의 비교 표본으로 학습된 추론을 우선하고, 부족하면 기준 계열의 완성된 관계를 전이한다. 이전 버전의 저장된 전이 결과는 재추론해야 바뀐다. 기존 수동 보정은 유지하므로 순수 추론을 보려면 해당 자소 보정을 초기화한다.
- `전이 기준 자동`은 같은 꼴/받침 유무에서 표본이 가장 많은 초성을 고정한다. 동률은 초성 순이다. 직접 초성을 지정할 수도 있다. 개별 조합이 없다고 다른 초성의 절대 박스로 바꾸지 않는다.
- 빠진 기준 조합은 실제 공통 표본 3쌍 이상이 있으면 기존 검증 기반 관계 모델로 보완한다. 부족하면 같은 모음 안의 실제 공통 받침을 연결점으로 너비/높이 변화율, X/Y 이동량을 적용하고 `검증 부족`으로 표시한다. 여러 연결점은 중앙값을 사용한다. 연결점 없는 조합은 근거 부족이며, 보완한 값을 새 학습 표본으로 사용하지 않는다.
- 보완한 기준 계열 전체에서 자소/꼴/받침 유무별 W/H를 정규화한다. 화면 필터나 대상 문자열을 바꿔도 범위가 바뀌지 않는다. 표본을 다시 분석하면 범위는 달라질 수 있다.
- 받친글자는 ㅁ 조건 기준으로 목표 WH와 XY를 구한 뒤 SVC location을 역산한다. 예: 맘 초성의 WH에 악/암 변화율을 곱하고 XY에는 악−암 이동을 더한다. 근거가 없으면 임시 위치로 적용하지 않는다. 수동 ΔXYWH는 한 번만 더한다. 민글자는 기존 별도 경로를 유지한다. 충돌 감지나 자소 간 자동 재배치는 아직 하지 않는다.
- 변화가 관측되지 않은 축의 비례는 미정(`None`)이다. SVC 평가에서는 0으로 두고 `관측 변화 없음`을 명시한다. 소스의 해당 축 범위는 추론된 것이 아니다. 기존 디자인은 빈 글립 적용 대상에서 제외한다.
- 받친글자의 중성·종성은 기본 경로의 실측이 부족하면 실제 비교 쌍으로 전이한다. 예: 막의 중성/종성 = 악의 해당 자소 × (맘/암의 해당 자소). X/Y에는 맘−암을 더한다. 같은 모음의 비교 쌍이 우선이다.
- 해당 모음의 기준 디자인이 없으면 같은 모임꼴 안에서 모음 간 전이를 허용한다. 예: 먹 초성 = 맘 초성 × (억 초성 / 암 초성). 중성·종성은 억에 암→맘 관계를 적용한다. `모음 간 전이`로 표시하며 실제 대상 디자인이 있으면 우선한다. H/V/M 사이에는 전이하지 않고, 실측 비교 쌍이나 목표 조건의 출발 표본이 없으면 근거 부족이다.
- 코너 안내도 이 모음 간 전이를 포함해 계산한다. 예를 들어 억·역의 초성이 악보다 좁다면 먹·멱의 추정 너비도 막보다 좁아진다. 계산 불가능한 조건은 여전히 전체 극값 보장의 대상이 아니다.
- Shift 클릭으로 연속 선택, Cmd/Ctrl 클릭으로 개별 추가/해제, `표시 글자 전체 선택`으로 필터 결과 전체 선택. 한 글자는 `이 글자 조정`, 여러 글자는 `선택 글자 함께 조정`만 표시한다.
- 여러 글자를 선택하면 모든 선택 글자의 현재 역할 박스를 강조한다. 크기 조절 핸들은 한 글자 선택일 때만 표시한다.
- `4코너 소스 만들기`에서 기존 소스를 찾으면 이름 입력란에 자동 입력하고 생성을 종료한다. 저장된 연결, 이전 명명 방식, 현재 명명 방식 순으로 찾으며 윤곽·레이어·note를 바꾸거나 자동 파생하지 않는다.
- `선택 글자 함께 조정 · unit`에 입력하면 현재 목표 공간 기준으로 임시 표시한다. `선택 글자에 적용` 전에는 저장값이 변하지 않는다. 공간/역할이 없는 대상은 제외한다.
- `직전 일괄 조정 되돌리기`는 한 단계만 지원하며 이후 개별 수정이 있으면 이를 덮어쓰지 않는다. 폰트 윤곽과 SVC는 이 배치 동작으로 변경하지 않는다.
- `계산 근거`에 상세 수치와 표본 관계를, `소스 준비·진단`에 디자인 안내·4코너 생성·개별 미리보기를 접어둔다. 일반적인 소스 연결·글자 생성은 펼치지 않고 실행한다.

## 글줄별 메트릭

- 각 글줄 바로 아래에 글자 advance에 맞춘 정보 행을 표시한다. 글립과 함께 가로/세로 스크롤한다.
- `비례 · 기준`: 기준 W/H 정규화 비율, 기준 문자, 실제 근거 표본, 상태. 단일/배치 보정값을 섞지 않은 기준 비례다.
- `공간 · unit`: SVC 평가 전에는 관계 참고/목표 X/Y/W/H, 평가 후에는 실제 SVC 윤곽의 XYWH와 `SVC 실제` 상태를 표시한다. 평가 후 참고 박스는 점선, SVC 박스는 실선이다. Δ 편집은 기존 참고 공간 대비 보정이며 실제 SVC 치수로 기준값을 덮어쓰지 않는다.
- `보정 · Δunit`: 기준 대비 변경량. 배치 미리보기도 즉시 표시하지만 적용 전에는 저장하지 않는다.
- 초성/중성/종성 정보 선택과 사이드패널 역할은 동기화한다. 정보 숨기기도 지원한다. 긴 출처 목록은 줄이고 전체 근거는 선택 후 사이드패널에서 확인한다.

## 4코너 디자인 안내

선택 자소 SVC의 `4코너 디자인할 글자 보기`에서 각 코너의 W/H 참고 치수와 대응하는 완성형 글자를 확인한다. 글자 전체가 아니라 선택한 역할의 자소를 디자인해 넣는다.

- 너비/높이 극값이 동시에 맞는 글자가 있으면 해당 글자를 안내한다.
- 없다면 가까운 출발 글자와 너비 참고/높이 참고 글자를 따로 표시한다. 이때 다른 치수도 함께 바뀌는 컨투어를 그대로 복사하면 안 되며, 독립적인 코너 디자인이 필요하다.
- 전이 계열의 안내는 기준 프로필 전체를 사용한다. 필터/대상 문자열에 따라 극값이 바뀌지 않으며, 대상 자소의 확정 크기로 표시하지 않는다. 수동 보정값도 기준 계열의 극값에 섞지 않는다.
- 대상 실측 기반 안내는 현재 목표 공간을 사용한다. 생성 가능한 대상 윤곽이 있으면 자동 초안도 같은 범위를 사용한다.
- 대상 자소 윤곽이 없어도 `4코너 소스 초안 만들기`를 실행할 수 있다. 이 경우 윤곽 없는 4개 레이어와 width/height 앵커를 만들고 소스를 연결한다. 대상 자소의 실측 윤곽이 있으면 기존처럼 복사·스케일 초안을 만든다.
- 생성 당시 조건/실측/레이어 안내는 소스 이름별로 Font lib와 glyph note에 저장된다. 안내창을 다시 열면 현재 표본 기준으로 조건을 재계산한다. 기존 소스 윤곽과 생성 당시 note는 변경하지 않는다.
- 빈 레이어를 채우기 전에는 location 미리보기와 SVC 적용을 거부한다. 기존 이름의 소스는 덮어쓰지 않는다. 안내만 보는 동작은 폰트를 변경하지 않는다.

### 이름과 위치

- 새 이름 예: `_hp.mieumCho-ko.H.closed.Thin`. 자소명/역할/모임꼴/받침 유무/마스터 순이다. 마스터 이름에 공백이나 특수문자가 있으면 정리된 이름과 해시를 함께 사용한다.
- 이전 `_hp.027f0b07.0.6.H.closed`는 마스터 해시/역할 인덱스/자소 인덱스/모임꼴/받침 유무였다. 기존 소스는 자동 개명하거나 덮어쓰지 않으며, 이전 이름의 소스가 있으면 중복 생성도 막는다.
- 안내에서 소스 내부 `(0, 0)`과 출발 글자의 완성형 내 X/Y/W/H를 구분한다. 합성 코너에 유일한 음절 배치 위치가 있다고 가정하지 않는다. 복사한 경우 실제 복사 표본과 원래 bbox도 생성 당시 안내에 보관한다.
- 실제 분석된 같은 자소·모임꼴·받침 유무의 윤곽만 복사한다. 다른 자소의 기준 표본이나 분석하지 않은 글자의 요소 역할을 추측해 복사하지 않는다.
- 2026-10-17 sticker API 조사: `flSticker`와 문서상 `flShape(flSticker)`는 있으나 현재 FontLab에서 생성자가 `flShapeBuilder` 오류를 반환했다. `shape.sticker`는 읽기 전용이었다. 객체 ID 변환을 시도하던 중 MCP 연결이 끊겼고 이후 연결 거부 상태였다. FontLab 종료 여부는 확인하지 못했다. 해당 우회 코드는 제품에 포함하지 않았으며, sticker 자동 추가는 미구현이다. 안내창/Font lib 저장을 사용한다.
